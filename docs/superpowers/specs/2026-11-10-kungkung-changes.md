# 킁킁 수정사항 구체화 (11/10 확정본)

> 원본: Claude 앱 프로젝트 문서 "킁킁 수정사항 구체화". 2026-11-11 사용자가 붙여 넣은 내용을 요약해 옮김.
> 기준 코드: develop ddee258. 프론트는 feature/home-design(펌킨 스파이스 디자인) 위에서 작업.

| 묶음 | 항목 | 범위 |
|------|------|------|
| A | 1 코스 삭제 | 백+프론트, 작음 |

## 1. 추천받은 코스 삭제
- 같은 가족이면 누구나 삭제. 다녀온 코스를 지워도 활동 기록(source=COURSE)은 유지.
- 버튼: 저장한 코스 목록 각 줄(휴지통, `e.preventDefault()`) + 코스 상세 하단 "코스 삭제". 확인 창 "이 코스를 삭제할까요?" 한 번. 삭제 후 `/courses`.
- 자동 저장은 그대로.
- 백엔드 `DELETE /api/courses/{courseId}`: `find(memberId, courseId)`로 권한(없으면 COURSE_NOT_FOUND) → course_place 삭제 → course 삭제.
- 테스트: 삭제 성공, 다른 가족 404, 다녀온 코스 삭제 후 활동 기록 유지.

## 2. 반려견 질병 맞춤 영양 가이드 (LLM 안 씀)
- 지병과 맞지 않는 SAFE 음식은 "주의"로 옮기고 이유를 "비만이 있어 조금만 주세요"처럼 지병 이름으로 표시.
- 매칭: `food_guide`에 지병 키 목록(예: 고구마·바나나 → OBESITY, 견과류·땅콩버터 → PANCREATITIS).
- 사료량: 비만만 계수 1.0 + "감량 기준 사료량". 다른 지병은 그대로.
- 화면: 맨 위 "○○ 맞춤 안내" 요약 박스(지병 + 핵심 한 줄), 지병 카드를 사료량 카드 위로.
- 자유 입력 지병: "등록된 안내가 없는 질환이에요. 식단은 수의사와 상의하세요."
- 응답 `FoodItem`에 `reasonTag`(ALLERGY/DISEASE).
- 테스트: 비만견 → 고구마 주의·계수 1.0, 지병 없음 → 기존과 동일, 자유 입력 지병 문구.

## 3. 홈 요약을 어제 하루로 (프론트만)
- 어제 하루만, ‹ › 없음. 제목 "어제 ○○ 건강 요약" + 날짜 배지.
- 문장 "어제 식사 2번, 산책·활동 30분 했어요. 배변은 안정적이에요." / 없으면 "어제 남긴 기록이 없어요. 오늘 있었던 일을 아래에 적어 보세요."
- 칩: 식사 n회 · 배변(좋아요/지켜보기) · 활동 n분 · 증상(없음/n회), 투약·병원 있으면 칩 추가. 상단 배지 "AI 상담 n회 · 기록 n개 기반"도 그날 기준.
- 하단 링크 "이번 달 기록 보기 →"(/records). summary API를 from=to=어제로.

## 4. 기록 저장 전 확인 단계 없애기 (프론트만, 추천안 1·2·3·5)
- 글 → 변환 → 바로 저장 → 그 날짜 기록 목록, 방금 저장한 항목 강조.
- 목록 상단 안내 바 "기록 3개를 저장했어요 [되돌리기]"(몇 초). 되돌리기 = 저장한 id들 DELETE.
- 값을 못 읽은 항목: 저장하고 안내 바에 "값을 못 읽은 항목 1개 → 눌러서 고치기".
- LLM 실패·0개면 지금처럼 직접 입력 카드(2단계 유지). 위험 음식 경고는 따로 안 띄움.

## 5. 기록 입력창과 AI 질문창 합치기
- 규칙으로 판별(LLM 없음): `?` 또는 의문형 어미(~까요, ~나요, ~ㄹ까, ~해도 돼, ~인가요, ~어떡해 등)면 질문.
- 질문이든 기록이든 입력한 글은 모두 기록으로 저장. 질문이면 기록 저장 + LLM 3개 상담 병렬. 순수 질문은 QUESTION(질문 메모)로 저장.
- 기록으로 처리되면 "AI에게 물어보기" 링크로 같은 글을 상담으로.
- 기록 문구: "콩이 보호자님! <입력하신 내용>을 저장하도록 하겠습니다 !" 후 바로 저장 → 기록 목록 + 되돌리기.
- 질문: 상담 결과 화면 `/consult/{id}`.
- 홈 섹션 제목 "기록하고 물어보세요". 기록·상담 화면 입력창도 같은 `UnifiedInput`. 상담 메뉴 유지.
- 백엔드에도 `IntentClassifier` + 예문 30개 단위 테스트(발표용 "정확도 n/30").

## 6. 상담 원문 90일 보관 후 정리 (B안, LLM 없음)
- 90일 지나면 `consultation_answer` 원문만 삭제, `consultation`의 질문·긴급도·병원 권유·종합 3줄은 남김.
- 매일 04:00 `@Scheduled`, `archived_at` 컬럼, 100건씩. 설정 `consult.retention-days: 90`.
- 화면: "90일이 지나 요약만 보관 중" 배지, 모델별 답변 대신 종합 3줄만. 기록은 삭제 안 함.
- 테스트: 89/91일 경계, 이미 정리된 건 건너뜀, 기록 테이블 그대로.

## 7. 사료 권장량을 g으로
- 사료 칼로리 모르면 3,500kcal/kg 기본값으로 "약 Ng" + "일반 건사료 기준이에요. 사료 봉투의 칼로리를 입력하면 더 정확해져요 →".
- 큰 숫자는 g만, kcal는 근거 줄 작은 글씨. "하루 2번이면 한 번에 약 Ng". 간식 "하루 열량의 10% 이내 (사료로 치면 약 Ng)". 비만이면 1.0 계수 g.
- 백엔드: `DEFAULT_FOOD_KCAL_PER_KG = 3500`, 응답 `foodGramsEstimated`, `foodGrams` 항상 값 있음.

## 8. 내 반려견 기록을 아는 상담
- 최근 14일 숫자 집계만: 식사·간식·배변(무른 변 횟수)·증상(횟수, 마지막 날짜)·투약·병원 횟수, 산책 하루 평균 분, 체중 변화(처음→마지막), 이상 신호 문장. 기록 원문은 안 보냄.
- 프롬프트: "반려견 정보" 다음에 "최근 14일 기록: ..." 2~4줄 + "기록은 참고용이고 판단은 질문 기준으로 하세요".
- 화면: "이번 답변에 사용한 내 기록" 접힌 상자. 기록 없으면 안 보냄·상자 없음. 지난 상담은 안 넣음.
- `Consultation.context_lines`(JSON), 90일 정리 때도 남김.
- 테스트: 기록 없음/있음 프롬프트 비교, 원문 메모가 프롬프트에 안 들어감.
